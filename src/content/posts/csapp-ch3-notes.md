> 这是一篇示例文章，用来演示博客的排版效果。内容随时可以替换成你自己的。

读《深入理解计算机系统》第三章最大的障碍不是指令集，而是**它假设你已经知道编译器在干什么**。下面三个点是我卡了比较久的地方。

## 1. 条件分支是"反着写"的

`if (a > b) { ... } else { ... }` 在 x86-64 里通常变成先判断相反条件、然后**跳过** then 分支：

```asm
    cmpq    %rsi, %rdi      ; 计算 rdi - rsi，只设标志位
    jle     .L3             ; a <= b 就跳到 else
    ; --- then 分支 ---
    ...
.L3:
    ; --- else 分支 ---
```

一开始我总把 `jle` 读成"满足则跳转"，结果控制流全画反。有效的练习方法是：**先找到跳转目标标号，再决定哪一段是"被跳过"的**。

## 2. 短路的证据在汇编里消失了

`if (p && *p > 0)` 会展开成两个独立的跳转——因为 `&&` 必须保证右侧不被执行。用 `gcc -O1 -S` 对比下面两个函数，能明显看到左移/右移的指令数量差别。

## 3. `leaq` 是唯一不做解引用的地址指令

```asm
leaq  9(,%rax,4), %rdx     ; rdx = rax * 4 + 9
```

这条指令经常被我误读成数组访问。它只是算数，不访存。理解了它之后，编译器做的那些 `i*n+j` 优化一下子就能看懂了。

---

作业做法：挑一段 10 行的 C 代码，先手写预测它的汇编，再用 `gcc -O1 -S main.c` 对答案。**错了的那几行才是这一章真正教会你的东西。**
