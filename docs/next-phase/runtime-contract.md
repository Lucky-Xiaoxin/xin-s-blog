## 2. 能力分层

| 层级 | 定义 | 例子 | 默认 |
| --- | --- | --- | --- |
| T0 构建期 | 不进入浏览器运行时 | KaTeX、Shiki、字体子集、RSS/sitemap、JSON-LD | ✅ 首选 |
| T1 一方 JS | 自己写的小脚本，无第三方请求 | 主题切换、代码复制、TOC 高亮、站内搜索 | ✅ 允许，需预算 |
| T2 第三方嵌入 | iframe/脚本来自外部服务 | 评论、统计、Newsletter、友链图标 | ⚠️ 逐项准入 |
| T3 后端/账号 | 自建服务、登录、数据库 | 自建评论、点赞、会员 | ❌ 本阶段不做 |

**原则**：能用 T0 解决就不用 T1；能用 T1 解决就不用 T2。T2 不是禁止，而是必须过准入清单。

## 3. T2 第三方准入清单

任何第三方能力进入站内前，必须在 PR/文档中回答：

1. **目的**：它解决什么具体问题？没有它，读者会损失什么？
2. **数据与隐私**：收集什么？是否 Cookie？是否可关闭？是否需要在关于页/隐私说明中披露？
3. **无 JS 降级**：脚本被禁用/被拦截时，页面是否仍可读、可反馈？
4. **主题与响应式**：是否跟随亮/暗主题？320px 是否可用？
5. **布局稳定**：是否预留高度，避免 CLS？是否懒加载（滚动到附近再加载）？
6. **性能预算**：初次加载多少 KB gzip？是否只在需要的页面加载？
7. **可退出**：是否有一行配置/开关能关掉？卸载后是否留下孤儿数据？
8. **维护成本**：服务免费额度、封禁/停服风险、审核责任谁承担？
9. **安全**：是否引入不可控脚本、iframe sandbox、Cookie/Storage 访问？
10. **验收**：哪个页面、哪个视口、哪个主题、什么操作算通过？

不满足以上任一项 → 不进。

| 指标 | 当前基线 | 上限 |
| --- | --- | --- |
| CSS gzip | 13.0 KB | 18 KB |
| 站内 JS（不含搜索） | 约 1.5 KB 内联 | 3 KB gzip |
| 搜索 chunk | — | 30 KB gzip，仅 `/search/` 加载 |
| 单篇第三方 JS | 0 | 50 KB gzip，仅在使用页加载 |
| 最大文章 HTML | 20.1 KB | 30 KB |
| 字体总量 | 1.36 MB | 1.5 MB |
| `dist`（不含内容图） | 1.5 MB | 2.6 MB |
| LCP / CLS / INP | 未测 | 2.5s / 0.1 / 200ms |
| Lighthouse a11y / SEO | 未测 | ≥95 / ≥95 |

当前值以根 README 的体积预算表为准；本表只定义运行时准入与上限。

补充规则：

- 第三方脚本不得放在 `<head>` 阻塞首屏；必须 `defer`/动态 import/滚动懒加载。
- 任何评论区必须预留高度；不得把正文推下去。
- 任何统计不得使用追踪像素、跨站画像、广告 ID；优先无 Cookie。
- 任何嵌入不得自动播放音视频。
- 新增 T1/T2 后，必须重测文章页的 LCP/CLS，并在 PR 里贴数字。

## 5. 可访问性契约

- 键盘可达：跳转链接、导航、主题开关、TOC、代码复制、上下篇、评论入口。
- 焦点可见：沿用 `:focus-visible` 红色 2px 外框；不得在新组件里移除。
- 标题层级：每页一个 h1；TOC/系列导航不得制造错误的标题大纲。
- 对比度：正文、meta、红底白字、代码 token 均需 ≥ WCAG AA；新增颜色必须用现有令牌或给出对比度计算。
- 动效：新增过渡/动画必须在 `prefers-reduced-motion: reduce` 下关闭或缩短到近乎无。
- 图片：内容图必须有 alt；装饰图 `aria-hidden`；图注与图片关联。
- 打印：强制亮色，隐藏交互控件；代码/表格避免跨页断裂。
- 320px：不得出现横向页面滚动；技术内容横向滚动限制在容器内。

## 7. 验证与发布

### `npm run verify`（P0 建立）

1. `astro check`。
2. 以 `BASE_PATH=/xin-s-blog/`、`SITE_URL=https://lucky-xiaoxin.github.io` 构建（跨平台 Node 脚本设置 env）。
3. `check-dist`：
   - 站内 `href/src` 不得出现未带 base 的根绝对路径；
   - 所有内部链接/锚点可解析；
   - `draft: true` 不得出现在 `dist/posts/`；
   - 每篇文章有 canonical/OG（JSON-LD 属 P1e，尚未纳入门禁）；
   - RSS/sitemap 含预期路由；
   - 体积超预算失败，并打印当前值/上限。
4. 输出一份简短报告（通过/失败项、当前体积）。

### CI

- PR：`check + build + check:dist`；失败不合并。
- main：同上 + deploy。
- Lighthouse / 外链巡检：P2，不阻塞发布；外链允许失败重试/白名单。

### 发布流程

- 框架改动：分支 → 本地 `verify` → 交用户本地试用 → 用户确认 → push → PR → 合并。
- 文章内容：用户直推 main；agent 不代写代改。
- 行为变更同步 AGENTS/README/TROUBLESHOOTING，并核对断言。
- 回滚：revert merge commit；不手改 `dist`。
