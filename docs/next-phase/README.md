## 1. 背景与定位

- 站点：`二进制与诗`，个人技术笔记站，读者是自己和学弟学妹。
- 技术：Astro 7 静态站，GitHub Pages 项目站子路径 `/xin-s-blog/`，单人维护。
- 现状：4 篇 Markdown；KaTeX、Shiki、中文字体子集均在构建期完成；客户端 JS 目前只有主题切换。
- 下一阶段的关键词：**可发现、可连读、可验证**；不是平台化，也不是推倒重做视觉。

## 3. 目标与非目标

### 目标

1. 任意文章 3 次点击内可达；长文可跳读。
2. 成组内容（课程笔记、题解、建站日志）能连续阅读。
3. 新增一篇的成本不增加：仍是一条命令 + push。
4. 每次框架改动可自动验证：类型、构建、子路径链接、草稿泄漏、体积。
5. 保持静态优先；新增 JS 必须有预算、降级和退出机制。
6. 让站点更像“有人在写的博客”，而不只是文章列表；具体能力见第 7 节待定项。

### 非目标（本阶段）

- 多作者、账号体系、权限、自建后端。
- 重型 CMS、数据库、服务端渲染。
- 视觉推倒重做；现有白底正红几何系统、Seal 映射、字体策略不推翻。
- 多语言、PWA、复杂动画、广告/追踪。
- 友链、评论、统计、Newsletter、点赞、Webmention：本阶段不做。
- 自动改写用户文章内容；系列归类等编辑决策必须用户确认。

## 5. 路线图

### P0：内容基础与质量门禁（已完成）

- 修复草稿预览：dev 可打开 `draft: true` 文章并显示草稿标记；build 产物绝不包含草稿；同步 README。
- 抽出 `src/lib/posts.ts` 统一数据访问：发布过滤、排序、按 slug 查找、相邻文章、标签聚合；首页/文章/标签/RSS 全部走它。
- 新增 `npm run verify`：生产子路径构建 + 死链/锚点/草稿泄漏/体积检查。
- 固化性能预算与验收矩阵（见 `runtime-contract.md`）。
- `/archive/` 与文章内联 TOC **不属于 P0**：归档归 P1a，TOC 归 P1d（见 `implementation-plan.md`）。

**P0 验收**：所有 P0 路由在 `/xin-s-blog/` 下可用；dev 能看草稿、dist 无草稿；`npm run verify` 全绿；文章页不新增 JS。

### P1：阅读体验与作者生活层（1–2 周，依赖 P0）

- 碎碎念：`/notes/` 流 + 首页最新 3 条；内容、展示、RSS 与发布方式见 `notes-contract.md`。
- now：`/now/` 静态页；内容模型、导航与更新流程见 `now-contract.md`。
- 设计落地：tokens/shell 宽度、首页卷首、文章页规格/TOC/编号、归档/标签/notes/now 版式，按 `design-contract.md` 的 P1a–P1e 拆分。
- 相关文章：共享标签算分，取前 3；无匹配不显示。
- 代码复制按钮：渐进增强，<2KB，无 JS 不显示。
- JSON-LD（BlogPosting / BreadcrumbList）与 OG 元信息补全。
- h4、图片图注、`prefers-reduced-motion`、打印规则。
- 移动端/键盘/读屏走查。

### P2：发现与运营（按需，逐项决策）

- 站内搜索：先验证中文分词、索引体积、子路径、无结果状态；不通过就不做。
- 逐篇 OG、旧链接重定向、字体死重清理、Lighthouse/外链巡检。
- 系列：等内容成组后再评估，不在 P2 预设时间点。
- 评论、统计、Newsletter、点赞、友链、Webmention：**暂不做**，未来另议；不占当前路线图。
- 每一项新能力都按 `runtime-contract.md` 的准入清单单独评审，可随时砍掉。

### 设计探索线（并行，不阻塞 P0）
