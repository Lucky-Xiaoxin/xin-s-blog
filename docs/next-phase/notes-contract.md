# 碎碎念契约

> 状态：已批准 · 2026-10-23；按本文与 `design-contract.md` 执行，实现中验证。
> 已确认：做 **碎碎念 + now**；now 单独见 `now-contract.md`；其它作者生活层功能暂不做；系列暂缓；设计范围 A/B/C/D，E（配色/字体）不动。

## 1. 为什么做碎碎念

当前站点只有 4 篇文章，看起来像“文章展示页”，不像“有人在写的博客”。碎碎念是最轻的“作者在场”信号：

- 成本低：一条几句话，不需要标题、摘要、封面、标签。
- 频率高：可以记录“今天在学什么/踩了什么坑/看到什么”。
- 不抢文章：文章仍是主体，碎碎念是侧流。

它解决的是 C（缺少作者生活感），不是靠给文章页加装饰。

## 2. 碎碎念是什么

**短、带时间、可独立阅读的笔记流。** 类似微博/朋友圈，但只在自己的站上，不追求互动。

| 维度 | 文章 | 碎碎念 |
| --- | --- | --- |
| 长度 | 长，完整论述 | 1–5 句，建议 ≤500 字 |
| 标题 | 必填 | **不要标题**；需要标题就写成文章 |
| 摘要 | 必填 | 不需要 |
| 结构 | 可以有章节、公式、代码 | 以短段落/链接为主；可少量代码/公式 |
| 顺序 | 按发布时间，可归档 | 按时间倒序，天然是流 |
| URL | `/posts/[slug]/` | `/notes/#[id]`（首版不单独生成页面） |
| RSS | 主 RSS | 独立 `/notes/rss.xml`（建议） |
| 标签 | 有 | 首版不做标签，避免污染文章标签体系 |

## 3. 内容模型

目录：`src/content/notes/`

文件命名：`YYYY-MM-DD-slug.md`，例如 `2026-10-22-design-agent.md`。`slug` 同时作为页面锚点。

```yaml
---
date: 2026-10-22
time: '19:40'      # 可选，纯显示；不参与日期运算
draft: false       # 可选，true 时 build 不生成；dev 可预览
---
今天把设计 brief 写完了。最大的收获是：先把“素”拆成 A/B/C/D，再谈视觉，不然设计 Agent 只会给一张更花的皮。
```

规则：

- 没有 `title`、`description`、`tags`；这些是文章字段，不要复用。
- 正文支持 Markdown：段落、链接、行内代码、引用、列表；**不建议**长代码块/大表格/多级标题。
- 图片可选，但必须写 alt；图片放 `src/content/notes/` 同目录或子目录，用相对路径。
- 日期只用于排序；`time` 只用于显示（与文章 `pubTime` 同一哲学：显式字面量，不引入时区运算）。
- 内容太长发不出去时，说明它应该是一篇文章，不是碎碎念。
- 一条只表达一件事；不强制“每条都有金句”。

## 4. 展示与路由

### `/notes/`

- 按时间倒序；按月份分组（如“2026 年 10 月”）。
- 每条显示：日期（+可选时间）、正文、固定链接锚点。**首版不显示 `N° 006`**（避免回填旧 note 导致编号漂移）；若以后要，需先定义稳定编号规则。
- 每条有稳定锚点：`/notes/#2026-10-22-design-agent`。
- 首版**不生成** `/notes/[slug]/` 独立页面；这样避免为几句话生成一堆页面、sitemap 和 OG。
- 页面标题/描述固定，例如“碎碎念 · 二进制与诗”。

### 首页

- 在文章列表上方放一个紧凑的“碎碎念”区块，显示最新 3 条 + “查看全部 →”。
- 不与文章混排：文章仍有标题/摘要/阅读时长，碎碎念没有；混排会破坏两种内容的阅读预期。
- 如果设计 Agent 认为首页太挤，可改为“最新 2 条 + 一行入口”；具体版式由设计稿定，但**默认 3 条**。

### RSS

- 建议独立 `/notes/rss.xml`；主 RSS 继续只发文章。
- 理由：订阅文章的人不一定会想收短笔记；分开更可控。
- 碎碎念页和页脚可以放“订阅碎碎念”链接；是否放由你定。

### Sitemap / SEO

- `/notes/` 进 sitemap；锚点不进。
- 不为每条碎碎念生成 `BlogPosting` 结构化数据；碎碎念是流，不是文章。
- 如果以后单独生成页面，再补 canonical/OG/JSON-LD。

## 5. 发布流程

首版建议**手动 Markdown**，不先做脚本：

1. 在 `src/content/notes/` 新建 `YYYY-MM-DD-slug.md`。
2. 按模板填 `date` / 可选 `time` / 正文。
3. `npm run dev` 预览（draft 也可预览，带草稿标记）。
4. 改 `draft: false` 或删掉 `draft`，push 到 main。

理由：碎碎念频率还不确定，先别为它加一个脚本；如果一周后觉得手写文件名麻烦，再加 `npm run note` 或 `新建碎碎念.bat`，提示语写在脚本里（因为你不爱翻 README）。

## 6. 校验规则

- `date` 必填；`time` 可选但必须是 `HH:MM`。
- 正文不能为空；去空白后至少 1 个字符。
- 文件名必须匹配 `YYYY-MM-DD-slug.md`；同一天多个 slug 可以。
- 同一 slug 重复 → 构建报错。
- 正文超过 800 字 → 构建警告（不阻断），提示“考虑写成文章”。
- `draft: true` 不得出现在 build 产物；dev 可预览。
- 未来日期 → 警告，不自动隐藏（与文章行为一致，避免引入隐式调度语义）。

## 7. 非目标

- 评论、点赞、转发、@ 提及。
- 每条独立页面、独立 OG、独立 RSS item 页面。
- 碎碎念标签页/标签云。
- 自动从 GitHub/微博/朋友圈同步。
- 图片九宫格、富文本编辑器、后台管理。
- 把碎碎念混进文章列表或文章 RSS（首版）。

## 8. 其它“作者生活层”选项（大白话）

| 功能 | 大白话 | 长什么样 | 代价 | 现在适合吗 |
| --- | --- | --- | --- | --- |
| 碎碎念 | 像微博/朋友圈，短、随时发 | 日期 + 几句话的流 | 低，纯静态 | **你已选，先做** |
| 友链 | 别人的博客链接墙 | 头像/站名/一句话/链接 | 低，纯静态；要维护链接 | 有常看的博客、想互相串门再做 |
| now | “我最近在干嘛”页 | 最近在学什么、读什么、做什么项目 | 低，手动更新 | **已选**，见 `now-contract.md` |
| 评论 | 读者在文章下留言 | 输入框、楼层、回复 | 中高：第三方脚本、审核、隐私 | 有人明确说想留言再做 |
| 统计 | 看有多少人看、哪篇受欢迎 | 后台数字/图表 | 低中：第三方脚本 | 想知道有没有人看再做 |
| Newsletter | 邮件订阅 | 输入邮箱，发新文章通知 | 高：第三方服务、隐私、退订 | 不建议现在 |
| 点赞 | 读者点个心 | 心形/数字 | 中：需要后端或第三方 | 不建议现在 |
| Webmention | 别的博客引用你，自动显示 | 跨站回复 | 高：协议/服务/审核 | 不建议现在 |
| 专栏/专题 | 无序主题集合 | 带说明的标签页 | 低 | 暂不新增类型；先增强标签页 |

**已定范围**：碎碎念 + now。其它（友链、评论、统计、Newsletter、点赞、Webmention）**暂不做**；以后要加，再按 `runtime-contract.md` 单独评审。

## 9. 已确认默认（2026-10-22）

| 编号 | 决定 |
| --- | --- |
| N1 | 首页放最新 3 条；太挤就 2 条 + 入口 |
| N2 | 首版不做每条独立页面；单页锚点足够 |
| N3 | 独立 `/notes/rss.xml`；主 RSS 保持文章 |
| N4 | 允许 Markdown/图片/代码/公式，但以短文本为主；图片必须 alt |
| N5 | 首版手动 Markdown；觉得麻烦再加 `npm run note` |
| N6 | 未来日期不隐藏；与文章一致，不引入调度语义 |
| N7 | 首版不进站内搜索 |

相关：`now-contract.md` 定义“最近在做什么”的静态页；两者不互相替代——now 是当前状态，碎碎念是带时间的流水。
