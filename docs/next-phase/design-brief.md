# 设计 Agent Brief（已废弃）

> 状态：**已废弃 · 2026-10-23**（已被 `design-contract.md` 取代，保留作 brief/取舍记录）。方向一「卷首」已选定，不再补设计稿、不再开设计轮次。
> 本文保留作 brief 与取舍记录，不是实现指令。
> 目标：解决“站点太素”的感觉，同时不推翻现有识别度、不拖慢 P0。

## 1. 先诊断“素”指什么

**用户已确认（2026-10-22）：A、B、C、D 都有；E 不动。**
其中 C 主要是功能缺口（还没有作者生活层），已收敛为 **碎碎念 + now**；设计只负责页面壳，内容模型先看 `notes-contract.md` 与 `now-contract.md`。不要让设计 Agent 直接“做个好看的 redesign”。先确认具体症状：

| 编号 | 可能含义 | 典型症状 |
| --- | --- | --- |
| A | 首页第一屏缺记忆点 | Hero 只有几何线稿，没有内容/作者/最近动态 |
| B | 文章阅读节奏单调 | 长文全是段落，缺少目录、引文、图、分隔、重点块 |
| C | 缺少作者生活感 | 只有技术文章，没有 now/碎碎念/照片 |
| D | 编辑感/内容密度不足 | 没有封面、专题策展、精选、编辑排版 |
| E | 配色/字体太克制 | 只有黑白红，想更温暖/更文学/更科技 |

**建议**：如果用户说不清，先按 A+B 做探索；C 属于内容层，不是视觉层；E 风险最高，容易破坏现有识别度，最后再动。

## 2. 必须保留的约束

- 白底 + 单一正红 + 黑/灰的基调；红仍是唯一重音。
- 几何描边语言（Hero、Seal、Badge、1px 规则线）；不换成圆角卡片堆叠。
- 标题 Bodoni Moda + 思源宋体子集；正文系统无衬线；等宽用于 meta。
- 正文 measure 42rem 左右；不为了“看起来丰富”把行宽拉到难读。
- 无渐变、无投影（题记的硬边雕刻是唯一例外）；不引入 UI 框架/组件库。
- 静态 Astro、零第三方脚本、GitHub Pages 子路径 `/xin-s-blog/`。
- KaTeX/Shiki/字体子集、`.scroll-x` 技术内容包装、明暗双入口、打印规则不可破坏。
- 320px 可用；亮/暗都要给稿；键盘焦点与对比度达标。
- 不使用带水印的 AI 生成图作为站点资产；配图优先 SVG/程序化/自有照片。

## 3. 可以动的范围

- 首页 Hero 构图、首屏信息层级、精选/最新/归档入口的组织。
- 文章头部：题记、meta、TOC、相关文章的视觉关系。
- 归档/标签/碎碎念页/now 页的版式与“编辑感”。
- 正文中的图注、引文、提示块、分隔、代码块标题栏。
- 少量装饰性几何图形/作者手绘元素；必须可 SVG、体积可控。
- 字号/间距比例的微调；不得牺牲正文可读性与 320px。

## 4. 交付物

设计 Agent 应交付 **2–3 个方向**，每个方向包含：

1. 一句话主张（这个方向让站点更像什么）。
2. 首页桌面 + 移动。
3. 文章页桌面 + 移动（含 TOC、相关文章、代码块、公式、图注）。
4. 归档/碎碎念/now/标签中至少 2 个页面；碎碎念需要首页区块 + `/notes/` 页的壳，now 需要 `/now/` 页的壳。
5. 亮色 + 暗色状态。
6. 关键组件规范：颜色令牌、字号/行高、间距、边框、hover/focus、按钮、标签、TOC。
7. 实施说明：哪些能用现有 CSS 完成，哪些需要新结构/新 JS；新增 JS 预算。
8. 不要只给 moodboard；优先 HTML/CSS 原型或带标注的高保真稿。

## 5. 评估标准

| 维度 | 问题 |
| --- | --- |
| 识别度 | 一眼还能认出是“二进制与诗”吗？不是通用博客模板？ |
| 阅读 | 长文更舒服还是更花？技术内容（代码/公式/表格）是否更清楚？ |
| 可实施 | 能否用现有 Astro/CSS 落地？是否需要引入新依赖/框架？ |
| 性能 | 新增图片/字体/JS 多少？是否守住 `runtime-contract.md` 预算？ |
| 可访问性 | 对比度、焦点、键盘、320px、减少动效是否成立？ |
| 延展性 | 归档/碎碎念/未来互动功能是否能沿用这套语言？ |

## 6. 流程

1. 用户勾选“素”的具体层面（第 1 节），并提供 2–3 个喜欢的参考站点（可选）。
2. 设计 Agent 在 1–2 天内给 2–3 个方向，不写生产代码。
3. 用户选 1 个方向；可以混合，但要明确取舍。
4. 把选定方向收敛成“设计契约”：令牌、组件、页面清单、验收标准。
5. 按 P1/P2 拆 PR 实施；**P0 不因设计探索停工**。

- 不改 URL、Seal 映射、标签形状、字体加载策略。
