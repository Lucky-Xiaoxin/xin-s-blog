S.01从一道签到题说起

题目概述：n 个整数 1，2，3，……，n 组成一个序列，两人轮流进行如下操作：如果当前剩余整数异或和不为 0，则可以选择从最左 / 右侧移除一个整数。若无法移动 / 异或和为 0，则输掉游戏，“我”先手。

T ≤ 105，n ≤ 106。看到这个数据范围，就知道不能真的去模拟——得先找一个能直接判断的性质。

最终成绩：3 题爆罚时，总排 177/228，正式队伍 172/220，唉……

赛后复盘时才发现，真正有用的不是“怎么移”，而是“剩下多少个数”。把前缀异或表摊开，答案就在周期里。

S.02前缀异或的周期

这里用到前缀异或和 S(k) = 1 ⊕ 2 ⊕ ⋯ ⊕ k。它有一个很短的四项周期：

EQ. 01 S(k)= { k,k mod 4=0, 1,k mod 4=1, k+1,k mod 4=2, 0,k mod 4=3.

或者换成一句话：连续四个正整数的异或和为 0。于是判断只剩 k mod 4，≤ 1 先手胜，否则先手败。

为什么是四个一组

把每个数写成二进制，连续四个数的最低两位一定恰好走完 00 → 01 → 10 → 11，异或起来是 0。更高位每两个数一组重复，成对抵消。这个观察不依赖 n 的具体大小，所以可以把 O(n) 的博弈直接压成 O(1)。

LISTING 01 · C++xor_prefix.cpp · 10 LOC
int prefix_xor(int k) {
    switch (k & 3) {
        case 0: return k;
        case 1: return 1;
        case 2: return k + 1;
        default: return 0;
    }
}

S.03把结论写成一页纸

边界情况

  • n = 1 时，先手直接取走唯一一个数，异或和归零。
  • k = 0 走 k mod 4 = 0 分支，返回值 0，和空序列一致。
  • 多测时不要把上一轮的答案带进下一轮；这题的 O(1) 很容易写对，也很容易在输入输出上翻车。

S.04留下的问题

如果规则改成每次只能移除一个数，结论还会这么整齐吗？我暂时没有继续推。先把前缀异或的周期记下来，下次遇到类似的博弈题，至少知道该往哪个方向看。
